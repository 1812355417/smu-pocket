## 0. 三处「和最初假设不一致」的地方（最关键）

这三条如果按最初的理解写代码，**都不会报错**，但结果是错的 —— 最难查的一类 bug。

| 最初的假设 | 实际情况 | 照假设写的后果 |
|---|---|---|
| 课表响应是**裸数组** `[ {...} ]` | 外层是**对象** `{ "code":0, "data":[...], "message":"成功" }` | 直接解码成 `List<CourseData>` 抛异常 |
| 成绩是 `{ "data": { "rows": [...] } }` 三层 | `{ "data":"", "rows":[...], "total":50 }` —— `rows` 与 `data` **平级**，`data` 是**空字符串** | 解出 `rows = emptyList()`，**不报错**，成绩页一片空白 |
| `zc` 是 Int、`zcjfs` 是 String | 整学期总表 `zc = "12,13"`（字符串）；`zcjfs = 88.2`（**数字**） | 类型对不上 → `JsonDecodingException`，且只在切到那条查询条件时才炸 |

另外 `xnxqdmc` 这个字段**不存在**，真实是 `xnxqmc`（"2025-2026-2"）+ `xnxqdm`（"202502"）。
写错字段名不会报错（kotlinx 会当未知字段忽略），只会静默变 null。

## 1. 课表

```http
POST /new/student/xskbcx/getCalendarWeekDatas
Content-Type: application/x-www-form-urlencoded

xnxqdm=202601&zc=201&d1=2026-10-26 00:00:00&d2=2026-11-02 00:00:00
```

### 两套返回形态（同一 URL，参数不同）

| | 整学期总表（实测 118 行） | 按周查询 |
|---|---|---|
| 顶层 | `{code, data, message}` | 同左 |
| `zc` 周次 | `"12,13"` / `"13,10,15,9,4"`（多周串，**字符串**） | **实测没有该字段**（早期样例里有 `zc:8`，两套都得容错） |
| `qsrq` 真实日期 | ❌ 没有 | ✅ `"2026-10-23"` |
| `sknrjj` 上课内容 | ❌ 没有 | ✅ `"形势与政策专题二"` |
| `jcdm` 节次串 | ❌ 没有（用 `ps`/`pe`） | ✅ `"0809"` / `"060708"` |
| `pe` 结束节 | ✅ `"04"` | ❌ 没有（只有 `ps`） |
| 字段总数 | 40 | 更少（约 7~9） |

**结论**：想要「上课内容 + 真实日期」就必须按周查；整学期总表只能拿到周次串。

### 关键字段（课表）

| 字段 | 含义 | 备注 |
|---|---|---|
| `kcmc` | 课程名称 | |
| `teaxms` | 教师姓名 | 118 行全部非空 |
| `jxcdmc` | 教学场地 | **118 行里有 25 行是空字符串** |
| `xq` | 星期几 | Int，1..7 |
| `zc` | 周次 | 字符串，可能是多周串 |
| `ps` / `pe` | 起始 / 结束节 | `"03"` / `"04"` |
| `jcdm` | 节次串 | `"0809"` = 第 8、9 节 |
| `qssj` / `jssj` | 上课起止时刻 | `"09:50:00"` / `"11:15:00"`，可直接当作息时间用 |
| `qsrq` | 上课日期 | 反推第一周周一的唯一依据 |
| `sknrjj` | 上课内容 | |
| `xnxqdm` | 学期代码 | `"202601"` |
| `bgcolor` | 教务自带的配色 | `"#1f86c7"`，可以直接用 |

### `zc=201` 已定案：是个固定值

2026-10 实测：**无论网页上选第几周，payload 里的 `zc` 恒为 `201`**。
响应里的周次是 1..20，所以请求的 `zc` **不是「第几周」**，而是个与周次无关的固定参数
（查询模式 / 批次号之类，具体含义不重要——反正不用变）。

→ **周次完全由 `d1`/`d2` 决定**。`RealJw` 里把它固化成 `FIXED_ZC = "201"`。

## 2. 成绩

```http
POST /new/student/xskccj/kccjDatas      ← 路径是推断的，待确认
Content-Type: application/x-www-form-urlencoded

xnxqdm=&page=1&rows=100
```

### 分页（必须处理）

实测 `total = 50`，但本次只返回 **20 行** → 服务器默认页大小 20。
只取第一页 = **只拿到 2/5 的成绩，而且不报错**。必须循环翻页直到累计 ≥ `total`。

### 关键字段（成绩）

| 字段 | 含义 | 类型 |
|---|---|---|
| `kcmc` / `kcywmc` | 课程中文名 / 英文名 | str |
| `xnxqmc` / `xnxqdm` | 学期名 `"2025-2026-2"` / 学期代码 `"202502"` | str |
| `zcj` | 总成绩（字符串） | **str** `"88.20"` |
| `zcjfs` | 总成绩分数 | **float** `88.2` |
| `cjjd` | 绩点 | **float** `3.8` |
| `xf` / `zxs` | 学分 / 总学时 | **float** `3.0` / `48.0` |
| `kcdlmc` | 课程大类 | `"公共基础课"` |
| `xdfsmc` | 修读方式 | `"必修"` |
| `ismax` / `isactive` | 重修取最高 / 是否有效 | `"1"` / `"1"` |
| `xsxm` / `xsbh` / `xsdm` | 姓名 / 学号 / 学生代码 | **隐私，不写入模型** |

`zcj` 和 `zcjfs` 存的是同一个成绩：前者字符串两位小数，后者浮点。
要算加权就统一用 `zcjfs`（精度规范），别混用。

## 3. 学期起点：不需要校历接口

南医大没有独立校历接口，但按周查询的课表带 `qsrq`，可以反推：

```
该周的周一 = qsrq - (xq - 1) 天
第一周周一 = 该周的周一 - (zc - 1) 周
```

两条独立真实记录验证过，都得 **2026-08-31**：

| 记录 | qsrq | xq | zc | 该周周一 | 反推第一周周一 |
|---|---|---|---|---|---|
| 形势与政策 | 2026-10-23（周五） | 5 | 8 | 2026-10-19 | 2026-08-31 |
| 临床诊断学 | 2026-10-08（周四） | 4 | 6 | 2026-10-05 | 2026-08-31 |

实现上**没有只取一条记录**，而是让每条记录投票取众数（`TimeUtils.inferFirstMonday`）——
单条记录可能是调课或录入错误。

**注意**：整学期总表没有 `qsrq`，反推不出来。所以 App 启动顺序必须是
「先发一次按周查询拿到日期 → 反推第一周 → 再渲染整学期」。

## 4. 实验进展

| # | 问题 | 结论 |
|---|---|---|
| 1 | 请求的 `zc` 是不是「第几周」 | ❌ 不是。恒为 `201`，与周次无关（2026-10 实测） |
| 2 | `d2` 传周日还是下周一 | ✅ **下周一**（左闭右开）：查第 9 周 = `d1=2026-10-26`、`d2=2026-11-02` |
| 3 | 按周查询的响应里有没有 `zc` | ❌ **没有**。按日期查，服务端不回传周次（见 §4.1） |
| 4 | 成绩 `rows=100` 是否真返回 100 行 | 待测（当前按每页 20 行翻页，无论哪种都能跑） |
| 5 | **宽区间（几个月）查询走哪一套形态** | 🔴 **待测**。这决定 `RealJw` 能不能自举出第一周周一 |

### 4.1 「响应里没有 zc」的连锁反应（已修）

原设计靠 `zc` 推第一周周一。没有 `zc` 会引发两处**静默失效**：

1. `inferFirstMonday` 拿不到周次 → 返回 null → 第一周永远算不出来；
2. `toCourse()` 的 `weeks` 为空 → 整门课被丢弃，**课表空白但接口 200**。

改法：把「第几周」的知情权交回调用方（发起请求的人本来就知道自己查的是第几周）：
- `TimeUtils.inferFirstMonday(records, queriedWeek = 9)`
- `CourseData.toCourse(fallbackWeek = 9)`

### 4.2 第一周周一怎么来（自举）

没有校历接口、按周响应又没有 `zc`，所以只能：

```
发一次宽区间查询 → 拿回带日期(qsrq)的课次
→ 每条算出所在周周一 → 取最小 → 就是第 1 周周一
```

**风险**：这里假设「宽区间查询会返回 `qsrq`」。已知按周有日期、整学期总表没日期，
但宽区间属于哪种还没测。若它也返回总表形态，`RealJw` 会抛
`IOException("宽区间查询没有返回上课日期…")` —— 此时改用
`RealJw(api, term, manualFirstMonday = LocalDate.of(2026, 8, 31))` 手填绕过。

## 6. 2026-10-30 真机联调修正（三条，都已改代码）

### 6.1 课表路径错了：`xskbcx` → `xsgrkb`

| 路径 | 结果 |
|---|---|
| `POST /new/student/xskbcx/getCalendarWeekDatas` | **404**（「页面不存在」） |
| `POST /new/student/xsgrkb/getCalendarWeekDatas` | **200** `text/json` ✅ |

原因：抓包时抄的是**页面 URL**（`xskbcx/main.page` 之类），真正的 XHR 走的是 `xsgrkb`（学生个人课表）。
和广中医规格里的 `/new/student/xsgrkb/getCalendarWeekDatas` 完全一致 —— 同厂商同命名。

### 6.2 未登录不是 401，是 HTTP 200 + `code:-401`

```json
{"code":-401,"data":"","message":"尚未登录，请先登录"}
```

**特别注意 `data` 是空字符串，不是数组。** 直接按 `List<CourseData>` 解会抛
`JsonDecodingException: Expected start of the array '[', but had '"'`，
把一个明明白白的「未登录」变成看不懂的解析错误。`JwJson.timetable()` 已改为先看 `code` 再取 `data`。

服务端也认这条 cookie：拿过期 cookie 请求，返回的就是上面这句 `尚未登录`。
→ **`code == -401` 一律翻译成 `SessionExpiredException`**，UI 直接引导重新扫码。

### 6.3 模拟器网络：DNS 是坑

- `zhjw.smu.edu.cn` 是**分域解析**：校内 DNS → `10.161.38.5`，公网 DNS（223.5.5.5）→ `202.192.1.45`，两个都能通 HTTPS。
- 这台机器宿主机有块「以太网 2」(172.20.10.1 手机热点)，其 DNS 已失效，
  模拟器的虚拟 DNS 转发到它就全废 → `UnknownHostException`。
- 修法：启动模拟器时加 `-dns-server 183.63.89.14`。
  **从 Android Studio Device Manager 启动不会带这个参数**，要写进
  AVD → Edit → Show Advanced Settings → Additional command line options。
- 不要在模拟器里用 `ping` 判断网络：QEMU/SLIRP 对 ICMP 支持不可靠，
  DNS 已经解析成功时 ping 外网 IP 依然可能全丢包。要测就测 TCP/HTTP。

## 7. 2026-10-30 二次实测：推翻前面的两条错误结论

上一轮（§4 表格、§6.1）有几条判断是错的。**以本节为准。**

### 7.1 `zc` 就是「第几周」，不是固定 201（推翻 §4 第 1 条、§6.1）

| 请求 | 返回 |
|---|---|
| `zc=1` | 10 门课，带 `qsrq` |
| `zc=9` | 13 门课，带 `qsrq` |
| `zc=20` | 1 门课 |
| `zc=`（空） | 整学期总表（无 `qsrq`、`zc` 是周次串） |
| `zc=201` | **空数组 `[]`** |

而且 `d1`/`d2` **完全不影响结果**（传错日期区间、传空，返回都一样）。

结论：**按周查课表只需要 `xnxqdm` + `zc` 两个参数。** `zc=201` 之所以之前"看起来是固定的"，
应该是抓错了字段（或看的是别的请求）。

### 7.2 第一周周一：查 `zc=1` 就能反推

`zc=1` 的 10 条记录全部指向 **2026-08-31**，不再需要宽区间自举。
`RealJw.deriveFirstMonday()` 已改为「查第 1 周 → 取 `qsrq-(xq-1)` 的最小值」。

总周数：`zc=` 空拿到整学期总表 → 取所有周次串的最大值 → 20。

### 7.3 成绩接口必须带 `source=kccjlist`（否则 403）

```http
POST /new/student/xskccj/kccjDatas
Content-Type: application/x-www-form-urlencoded

xnxqdm=&source=kccjlist&ismax=1&page=1&rows=200
```

- 少了 `source` → **HTTP 403 + 一页 HTML「错误提示」**（不是 JSON！）
- `rows=200` 时一次返回全部 50 条，`total=50`，无需翻页
- 响应 `Content-Type` 是 `text/html;charset=UTF-8`，但**响应体是 JSON** —— 别被 header 骗了

字段来源：`kccjList.page` 里的 `var queryParams = {xnxqdm, source:"kccjlist", ismax:'1', primarySort}`。

### 7.4 `Referer` 是硬性要求

同一个请求，不带 `Referer` → `{"code":-401,"message":"疑似非法请求，请刷新页面重新登陆后重新操作"}`；
带上任意本站 `Referer`（根路径、`/new/`、具体页面都行）→ 正常返回。

注意和学习到的区分：
- `疑似非法请求…` = **缺 Referer / 请求形态不对**
- `尚未登录，请先登录` = **cookie 过期**

`BrowserHeadersInterceptor` 已经自动补 `Referer`，业务代码不用管。

### 7.5 一次成功的真实响应（第 9 周，2026-10-26 起）

13 门课，每门都带齐：课程名 / 星期 / 起止节 / 教室 / 真实日期 / 上课内容。
示例：

`手术学基础 | 周1 第2-5节 | 手术学基础实验室(1)(本部) | 2026-10-26 | 外科洗手+打结，穿无菌手术衣…`

注意：按周查询的响应里**没有 `jcdm`**（节次串），节次来自 `ps`/`pe`，
`TimeUtils.sectionsOf()` 已经做了这个回退。
